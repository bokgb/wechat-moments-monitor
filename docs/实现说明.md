# 实现说明

`app.py` 和 `ui_layout.py` 提供独立 Tk 窗口；`engine.py` 负责好友首页监控，`album.py` 扫描个人相册，`batch_engine.py` 只执行当前补赞批次。扫描与点赞计划保存在 `ledger.py`、`album_store.py` 管理的本机 SQLite 中。

`local_reader.py` 限定数据库读取范围为联系人和朋友圈。底层 `read_backend` 来自 NOTICE 中注明的开源项目。密钥只保留在内存，本程序的临时解密缓存与源微信文件分开；不直接改写微信 SQLite。

`native_client.py` 以本机 JSON 请求调用 `MomentsBridge.exe`。桥接组件核对目标进程归属、加载 `MomentsNativeV10.dll` 并调用原生入口。DLL 检查微信版本和函数特征，使用微信任务队列完成刷新、原生缓存同步和点赞。没有对外监听端口，不提供聊天发送接口。

微信 4.2.0.13 的联系人库可能使用二进制 SQLCipher 口令。读取时按各库的文件头 salt 派生密钥，再验证数据页 HMAC。原有 raw-key literal 格式继续保留。两种格式都经过页校验，口令与密钥仅在进程内存中使用。

个人相册首页可能携带缓存校验值，服务返回空列表表示内容未变化。此时改用不携带旧首页校验值的 unsigned 上界分页起点补读，并保留置顶返回记录；空首页不覆盖原相册缓存。分页和作者核对通过后才保存扫描进度。

全局监控与指定补赞共用每账号、每帖子的去重记录。批次关系可以引用同一个原计划，不重新随机或重复提交。点赞前先落盘提交状态；结果不明确则保留，避免自动重发。成功时间为本机回读确认的时间。

源码测试使用模拟数据，不需要微信登录。隐藏界面检查不会显示窗口、控制微信或执行点赞。适配依赖特定微信二进制，升级微信后需要重新核对，不能仅修改版本号。
